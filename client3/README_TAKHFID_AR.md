# التخفيض الصح — التطبيق البديل (client3)

مجلد مستقل لتجهيز واجهة متجر بديلة مبنية على TStore وربطها بخادم Flask الحالي.

## الحالة الحالية

- `PLAN_AR.md`: خطة التنفيذ والاختبار.
- `API_MAPPING_AR.md`: خريطة API أولية، مع توضيح المسارات التي تحتاج تحققاً.
- `UPSTREAM_IMPORT_AR.md`: مصدر النسخة وملاحظات الترخيص.
- تم نسخ مصدر TStore إلى هذا المجلد، لكن **لم يكتمل ربطه بخادم Flask بعد**.
- يهيئ المصدر الحالي Supabase داخل `lib/main_development.dart` و`lib/main_production.dart`؛ تغيير عنوان URL وحده لن يربطه بخادم التخفيض الصح.
- README المصدر يعلن MIT، لكن ملف `LICENSE` لم يظهر في شجرة المصدر التي تمت مراجعتها. تحقق من الترخيص الفعلي قبل النشر العام أو التوزيع التجاري.

## فحص المصدر الحالي

ابدأ من مجلد `client3/`:

```bash
flutter pub get
flutter analyze
flutter test
```

قد يتوقف التشغيل أو البناء قبل إنهاء ترحيل الاتصال بسبب اعتماد المصدر على ملف `.env` وتهيئة Supabase. لا تضع مفاتيح حقيقية في Git. لا يوجد `lib/main.dart` افتراضي في المصدر؛ يستخدم المشروع نقطتي دخول منفصلتين.

## أمر التشغيل المستهدف بعد إكمال المرحلة الأولى

بعد نقل تهيئة التطبيق إلى Flask وإزالة التهيئة الإلزامية لـSupabase من مسار التشغيل:

```bash
flutter run -t lib/main_development.dart --dart-define=API_BASE_URL=https://takhfidsh.alattab.site/api/v1
flutter build apk -t lib/main_production.dart --dart-define=API_BASE_URL=https://takhfidsh.alattab.site/api/v1
```

الأمران أعلاه هدف التنفيذ بعد التعديل، وليسا دليلاً على أن النسخة الحالية متصلة أو جاهزة للبناء الإنتاجي.

## قواعد العمل

- جميع تعديلات التطبيق الثالث داخل `client3/`.
- لا تعدل `client/` أو `client2/`.
- لا تفعّل الدفع الحقيقي قبل اعتماد تكامله واختباره.
- لا تعتبر أي شاشة مكتملة حتى تعرض بيانات من Flask وتتعامل مع التحميل والفراغ والفشل.
