# سجل تنفيذ المراحل — client3

## المرحلة 0 — تثبيت خط الأساس

- فحوص CI الأولية نجحت في حل التبعيات واختبارات Flutter وتحليل Dart.
- فشل بناء APK في المحاولة الأولى بسبب مسار Java ثابت من جهاز Windows داخل android/gradle.properties؛ أزيل المسار الثابت حتى يستخدم Gradle بيئة Java لدى runner.
- أصبح بناء APK اختيارياً عند تشغيل سير العمل يدوياً، حتى لا يتكرر انتظار البناء الطويل مع كل تغيير صغير.

## المرحلة 1أ — أساس الاتصال بخادم Flask

أضيفت ملفات البنية التالية:
- lib/core/network/api_config.dart: عنوان API مركزي قابل للتبديل، تطبيع عنوان الخادم، وحل روابط الصور من جذر المضيف.
- lib/core/network/flask_api_client.dart: عميل Dio مركزي لطلبات GET وPOST وPATCH وDELETE، مع مهلات وBearer token اختياري وتوحيد أخطاء Flask.
- test/unit/core/flask_api_client_test.dart: اختبارات عنوان API وروابط الوسائط ومسار /api/v1 وAuthorization ورفض العناوين الخارجية واستجابة error/detail.
- لم توصل الطبقة بعد بمستودعات المنتجات أو المصادقة ولم تُزل تهيئة Supabase؛ ذلك متعمد حتى تُراجع الاستجابات وتُنشأ المحولات في مرحلة منفصلة.

معيار القبول: نجاح اختبارات client3 وتحليل Dart في Client3 Flutter CI. لا يشترط بناء APK في هذه المرحلة.

## الحد الفاصل

بعد قبول هذه المرحلة، المرحلة التالية هي تدقيق مسارات Flask الفعلية واستجاباتها، ثم ربط نطاق واحد محدود (الكتالوج) بواسطة محولات بيانات. لن تبدأ المرحلة التالية دون موافقة صاحب المشروع.
