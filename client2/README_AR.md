# client2 — التطبيق البديل (مرحلة الفحص والربط)

> **الحالة الحالية:** ملفا الفحص وخريطة الربط فقط؛ لم تُنسخ ملفات المصدر بعد، ولا يُعد هذا المجلد حاليًا مشروع Flutter جاهزًا للبناء.

## قواعد العزل

- التطبيق القديم يبقى في `client/` دون تعديل.
- كل ملفات النسخة الجديدة يجب أن تكون داخل `client2/`.
- لا تغييرات على Flask أو قاعدة البيانات أو إعدادات النشر ضمن هذه المرحلة.
- لا يُعاد تصميم شاشات المصدر. يتم عزل توافق البيانات والاتصال في طبقة الخدمات والمحوّلات.

- المستودع: https://github.com/mosesmbadi/Flutter-Multivendor-Mobile-app-for-WooCommerce
- الفرع الذي يحتوي التطبيق: `Khurshidbek_18` (وليس `main`).

- لا يظهر ملف `LICENSE` أو تصريح ترخيص في بيانات GitHub التي فُحصت. كما يذكر README للمصدر أن الرافع اشترى الكود من CodeCanyon: https://codecanyon.net/item/flutter-multivendor-mobile-app-for-woocommerce/28267063

لأن المستودع المصدر لا يثبت وجود رخصة تسمح بإعادة نشر الشفرة والأصول، لم تُنسخ هذه الملفات إلى مستودعنا العام. قبل استيرادها يلزم التحقق من رخصة الشراء أو الحصول على ترخيص مكتوب يشمل الاستخدام وإعادة النشر المطلوبة.

## نتائج المطابقة التقنية

1. المصدر تطبيق Flutter مبني لبيئة WordPress/WooCommerce؛ يستخدم طلبات `wp-admin/admin-ajax.php`، وواجهات `wp-json/wc/v2`، وملفات تعريف الارتباط ومفاتيح WooCommerce.
2. تطبيقنا الحالي في `client/` يستهلك واجهات Flask تحت `/api/v1`، ويستخدم `Authorization: Bearer` ورموز OTP، مع نماذج بيانات مخصصة.
3. مصدر WooCommerce يعلن Dart SDK قديمًا `>=2.7.0 <3.0.0`، بينما التطبيق الحالي يستخدم `>=3.12.0 <4.0.0`. يلزم تحديث التبعيات والتوافق مع Dart الحديث دون تغيير ملفات الواجهات بصريًا.
4. لا ينبغي نقل `local.properties` أو ملفات Firebase الخاصة أو مفاتيح API/الدفع الموجودة في المصدر إلى نسختنا. يجب تجهيز إعدادات مستقلة وآمنة لـ `client2`.
5. ملف [خريطة الربط](API_MAPPING_AR.md) يحدد المسارات المتاحة، والميزات التي تحتاج مواءمة أو بديلًا من الخادم.

## ترتيب التنفيذ بعد حسم الترخيص

1. استيراد المصدر المرخّص إلى `client2/` دون مجلد `.git` أو بيانات بناء/أسرار.
2. تثبيت نقطة دخول مستقلة ومعرّف تطبيق مستقل عن `client/`.
3. إضافة محوّلات Flask إلى طبقة API والنماذج، وعدم تعديل Widgets والشاشات إلا عند ضرورة تقنية مثبتة.
4. معالجة الميزات التي لا يقابلها endpoint في الخادم، كل ميزة على حدة.
5. التحقق باستخدام `flutter pub get` و`flutter analyze` والاختبارات، ثم مقارنة تغييرات Git للتأكد أن `client/` لم يتغير.

لا يتم النشر أو إجراء أي تعديل على تطبيق الإنتاج ضمن هذه الخطوات.
