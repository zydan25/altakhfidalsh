## نتائج المطابقة التقنية

1. المصدر تطبيق Flutter لبيئة WordPress/WooCommerce؛ يستخدم طلبات `wp-admin/admin-ajax.php`، وواجهات `wp-json/wc/v2`، وملفات تعريف الارتباط ومفاتيح WooCommerce.
2. تطبيقنا الحالي في `client/` يستهلك واجهات Flask تحت `/api/v1`، ويستخدم `Authorization: Bearer` ورموز OTP، مع نماذج بيانات مخصصة.
3. مصدر WooCommerce يعلن Dart SDK قديمًا `>=2.7.0 <3.0.0`. نبدأ باختبار المشروع على سلسلة Flutter متوافقة مع الشفرة القديمة، ولا نرفع قيود SDK أو الحزم الرئيسية إلا إذا أثبتت نتائج البناء أن ذلك ضروري.
4. لا ينبغي نقل `local.properties` أو ملفات Firebase الخاصة أو مفاتيح API/الدفع الموجودة في المصدر إلى نسختنا.
5. [خريطة الربط](API_MAPPING_AR.md) تحدد المسارات والميزات التي تحتاج مواءمة.

## ما أُضيف إلى client2

- `pubspec.yaml`: حزمة Flutter/Dart مستقلة عن `client/`.
- `lib/src/flask_api_client.dart`: عميل HTTP عام يتعامل مع JSON وBearer token، ويحلّ روابط الوسائط، ويعرض أخطاء Flask، ويدعم multipart، ويعرّف مسارات العميل الأساسية.
- `test/flask_api_client_test.dart`: اختبارات وحدات لعنوان API، والتوثيق، والأخطاء، وروابط الوسائط.

تم نقل الشاشات والأصول الأصلية إلى هذا المجلد، مع إبقاء طبقة الاتصال الجديدة مستقلة. ما زالت مواءمة النماذج وربط كل الميزات بالخادم عملًا لاحقًا. سير العمل `.github/workflows/client2-ci.yml` يفحص التبعيات والاختبارات والتحليل وبناء Android؛ راجع نتيجة GitHub Actions قبل اعتبار البناء ناجحًا.
